# Sonrisa DEV runtime workflows

These three reviewed workflows are manual and inactive. The editable Code-node bodies are in `runtime/`, fixed parameterized queries in `sql/`, SDK templates in `sdk/`, and sanitized snapshots in `workflows/`. EF migrations own the product tables. n8n reads enabled alerts and shared user notification destinations, evaluates one magnitude condition, and persists delivery snapshots; it does not own configuration or schema changes.

## Reproduce and inspect

Run `node --test n8n/tests/*.test.mjs`. Generate default SDK code for MCP validation with `node n8n/build-workflow.mjs ingest`, `node n8n/build-workflow.mjs evaluate`, and `node n8n/build-workflow.mjs deliver`. The helper embeds the current exact Code and SQL files; no package installation is needed. To compare a fresh remote snapshot with a tracked export, save the remote details to a local file outside Git, run `node n8n/export-workflow.mjs ingest /path/to/remote-ingest.json > /tmp/sonrisa-ingest.json`, then `cmp /tmp/sonrisa-ingest.json n8n/workflows/ingest.json` (likewise for `evaluate` and `deliver`). Pass `-` instead of a path to read the snapshot from stdin. Regenerate the tracked exports only after inspecting the changed remote definition and restoring operator defaults. The exporter rejects active workflows, changed source/SQL, unexpected connections and temporary operator inputs.

The `workflows/*.json` files were generated from actual inactive remote snapshots with safe defaults restored. Milestone 5 artifacts were refreshed after execution 29. The SMTP extension refreshes the changed evaluation/delivery artifacts from their actual tested remote definitions; see the separate SMTP validation record for the final executions. For MCP details, save only the response's `workflow` object as the CLI input. The exported JSON omits credential bindings, pin data, workflow/version/project/history metadata and remote webhook IDs. Rebind the intended DEV PostgreSQL product-access credential on every Postgres node and the intended Slack credential on the Slack node and SMTP credential on the Send Email node after import. Inspect each selected credential in n8n; an automatic credential choice may refer to another account. Confirm the PostgreSQL target is the product `sonrisa_dev` database before execution. Never put secrets or connection-string values in these files.

### Workflow entry points

1. **Ingest:** Leave `Operator ingest input` at `mode=live`, `fixture_json=` empty. Manually run **Sonrisa - Ingest Earthquakes - DEV** to fetch the current USGS all-hour GeoJSON and insert unseen `(source, external_id)` records. A repeated fetch retains the first accepted snapshot. The feed covers the current hour; an outage beyond that window can lose events. To test synthetic records, change only the operator fields to `mode=fixture` and paste the JSON from `fixtures/earthquakes.json`. The selector forces source `demo.usgs` and sends this branch through the same normalizer. Restore `live` and an empty fixture field immediately afterward. `node n8n/build-workflow.mjs ingest --fixture earthquakes.json` provides a reproducible temporary SDK reference; running it without the option shows the defaults. Do not connect a future schedule through the fixture selector.
2. **Evaluate:** Manually run **Sonrisa - Evaluate Pending Events - DEV** once per pending event. It reads the oldest pending event, loads enabled alerts across all owners with their shared user destinations, evaluates `earthquake/magnitude/gte/number`, inserts any intents idempotently, then marks the event evaluated. An empty queue performs no writes. Zero matches still produce an insert-count row and complete the selected event. If a DB step fails, stop and inspect the pending event; replay may add intents under a later configuration snapshot without retracting earlier ones. New Slack/email intents begin pending. Pre-extension email intents retain `unsupported`/`transport_not_implemented`; they are not backfilled or claimed.
3. **Deliver:** Confirm the selected alert, immutable destination and intended transport credential. Set one pending delivery UUID in `Operator delivery ID`, confirm the non-secret `sender_email` for email, and run **Sonrisa - Deliver Notification - DEV** once. Its empty default ID fails before the shared claim. The atomic claim accepts supported Pending Slack/email only; zero rows stop before either transport. Explicit channel guards route to the correct node. Slack retains plain-text escaping, disabled mentions/unfurls and its reviewed acknowledgement/rejection handling. Email uses one conservatively validated bare recipient, plain text and no CC/BCC/attachments. Invalid email preparation records Failed/`invalid_email_message` without sending. SMTP acceptance requires exactly the intended recipient and no rejected recipients; malformed results/errors remain Processing/`delivery_outcome_unknown`. There is no automatic retry, reset or backlog drain. Do not replay saved downstream nodes past the claim. Restore the ID to empty after testing; `node n8n/build-workflow.mjs deliver --delivery-id <uuid>` emits a temporary operator reference, while the command without the option uses safe defaults.

The accepted future polling design is five minutes UTC, connected directly to **Fetch USGS all-hour feed** so it cannot enter the fixture branch. No schedule is present or active in this milestone. Enabling unattended polling, retry and recovery requires a later reviewed change.
