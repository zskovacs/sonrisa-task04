# Sonrisa DEV runtime workflows

These three reviewed workflows are manual and inactive. The editable Code-node bodies are in `runtime/`, fixed parameterized queries in `sql/`, SDK templates in `sdk/`, and sanitized snapshots in `workflows/`. EF migrations own the product tables. n8n reads enabled alerts and shared user notification destinations, evaluates one magnitude condition, and persists delivery snapshots; it does not own configuration or schema changes.

## Reproduce and inspect

Run `node --test n8n/tests/*.test.mjs`. Generate default SDK code for MCP validation with `node n8n/build-workflow.mjs ingest`, `node n8n/build-workflow.mjs evaluate`, and `node n8n/build-workflow.mjs deliver`. The helper embeds the current exact Code and SQL files; no package installation is needed. To compare a fresh remote snapshot with a tracked export, save the remote details to a local file outside Git, run `node n8n/export-workflow.mjs ingest /path/to/remote-ingest.json > /tmp/sonrisa-ingest.json`, then `cmp /tmp/sonrisa-ingest.json n8n/workflows/ingest.json` (likewise for `evaluate` and `deliver`). Pass `-` instead of a path to read the snapshot from stdin. Regenerate the tracked exports only after inspecting the changed remote definition and restoring operator defaults. The exporter rejects active workflows, changed source/SQL, unexpected connections and temporary operator inputs.

The `workflows/*.json` files were generated from actual inactive remote snapshots with safe defaults restored. All three artifacts were refreshed from the final inactive remote definitions after execution 29; repeat this check after later workflow changes. For MCP details, save only the response's `workflow` object as the CLI input. The exported JSON omits credential bindings, pin data, workflow/version/project/history metadata and remote webhook IDs. Rebind the intended DEV PostgreSQL product-access credential on every Postgres node and the intended Slack credential on the one Slack node after import. Inspect each selected credential in n8n; an automatic credential choice may refer to another account. Confirm the PostgreSQL target is the product `sonrisa_dev` database before execution. Never put secrets or connection-string values in these files.

### Workflow entry points

1. **Ingest:** Leave `Operator ingest input` at `mode=live`, `fixture_json=` empty. Manually run **Sonrisa - Ingest Earthquakes - DEV** to fetch the current USGS all-hour GeoJSON and insert unseen `(source, external_id)` records. A repeated fetch retains the first accepted snapshot. The feed covers the current hour; an outage beyond that window can lose events. To test synthetic records, change only the operator fields to `mode=fixture` and paste the JSON from `fixtures/earthquakes.json`. The selector forces source `demo.usgs` and sends this branch through the same normalizer. Restore `live` and an empty fixture field immediately afterward. `node n8n/build-workflow.mjs ingest --fixture earthquakes.json` provides a reproducible temporary SDK reference; running it without the option shows the defaults. Do not connect a future schedule through the fixture selector.
2. **Evaluate:** Manually run **Sonrisa - Evaluate Pending Events - DEV** once per pending event. It reads the oldest pending event, loads enabled alerts across all owners with their shared user destinations, evaluates `earthquake/magnitude/gte/number`, inserts any intents idempotently, then marks the event evaluated. An empty queue performs no writes. Zero matches still produce an insert-count row and complete the selected event. If a DB step fails, stop and inspect the pending event; replay may add intents under a later configuration snapshot without retracting earlier ones. Slack intents begin pending; email intents are `unsupported` with `transport_not_implemented`.
3. **Deliver:** Confirm the selected alert, immutable delivery destination, approved DEV Slack credential and explicitly authorized channel. Set the exact pending Slack delivery UUID in `Operator delivery ID` and run **Sonrisa - Deliver Slack Notification - DEV** once. The default empty field fails before the DB claim or send. The conditional pending-to-processing claim is the only path to the Slack node. It sends one escaped plain-text message derived from the stored event and IDs, with mention parsing and unfurls disabled. An acknowledged send is recorded as `sent`. An exact known rejection is `failed`; uncertain transport errors remain `processing` with `delivery_outcome_unknown`. A crash after claim or after Slack accepts the message can also leave `processing`. There is no automatic retry, reset or backlog drain. Do not replay saved downstream nodes past the claim. Inspect n8n execution and database state before any further action. Restore the delivery ID to empty after the run. `node n8n/build-workflow.mjs deliver --delivery-id <uuid>` provides a temporary SDK reference; the command without the option shows the safe default.

The accepted future polling design is five minutes UTC, connected directly to **Fetch USGS all-hour feed** so it cannot enter the fixture branch. No schedule is present or active in this milestone. Enabling unattended polling, retry and recovery requires a later reviewed change.
