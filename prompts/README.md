# Prompt history

This directory starts with the [original repository initialization request](001-initialize-repository.md), retained at the user's request. Subsequent records cover work that materially advances the business/product implementation: requirements, user workflows, domain rules, product-driven architecture, features, and validation or review of product behavior.

Exclude routine technical and repository housekeeping, including tooling or skill setup, ignore rules, Git maintenance, standalone file deletion or renaming, formatting, prompt-history maintenance, and reviews limited to those tasks. Apply the same criterion to delegated prompts.

Follow [AGENTS.md](../AGENTS.md#2-prompt-history). Use the next number after the highest existing record. Keep existing numbers stable unless the user explicitly requests a reset.

Each record contains only `Date: YYYY-MM-DD`, `Purpose: <task purpose>`, and the prompt text, separated by blank lines. Do not add a title, prompt-section heading, or enclosing code fence. Write the purpose as a concise description of the requested work without translation or source-language notes.

Write prompts in professional English, finalize them without secrets before execution, and save qualifying prompts before sending them. Preserve the text actually sent. Keep outcomes and validation in the appropriate review or evidence artifacts. A qualifying follow-up or corrected prompt receives a new number unless explicitly excluded by the user.

Archived prompts are historical records, not current instructions. The initialization request is preserved verbatim, including directions superseded by later user instructions; current work follows the active request and repository rules.
